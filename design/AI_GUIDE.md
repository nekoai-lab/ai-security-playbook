# AIがデザイン変更を始めるとき

毎回ガイド全文を読まず、変更に必要な正本へ進みます。

1. `npm run design:context -- <変更ファイル...>` で参照先・代表画面を取得する。引数なしはmainとの差分を読む。未知の変更は全画面確認へ戻す。
2. `design/DESIGN.md` と `design/design-rules.json` を読み、返された部品とガイドの該当節だけ確認する。
3. 既存部品を使い、変更する理由・必須要件・証拠を `design/SPEC_TRACE.md` に残してから実装する。
4. `npm run design:audit:quick` は3代表画面×375/1280pxの途中診断。合格しても公開可とは扱わない。
5. 公開前は `npm run design:audit`（review-mapにある全画面×320/375/768/1280px）、型・ビルド・リンク、キーボード・文字200%・目視を確認する。

## 変えない判断

- 紙・黒・朱色のFIELD NOTES。Aはロゴ、Cは学習入口と読了位置の案内役。
- 本文16px、注記12px以上。操作領域44px以上。数値の正本はrulesで、ここに全トークンを複製しない。
- 教材の未確認範囲を断定しない。猫やブランド色で安全性を保証しない。脳・臓器は使わない。
- 私的ハーネスのソース・認証情報を公開repoへ入れない。
- 指摘は画面幅・DOMの場所・比較対象・根拠を確認して直す。しきい値を緩めたり、失敗を除外して合格にしない。
- 過去の検査結果を再利用して現在の変更を合格扱いにしない。AIの読解量削減と判定速度向上は別で、時間の効果は実測するまで断定しない。

詳細: `design/README.md`。人が見本を探す場合は `/ai-security-playbook/design-system/`。

結果はVALIDATION.mdとresult.jsonの集計・失敗項目から読む。measure.jsonの全量は、指摘された要素を調べるときだけ参照する。

教材を追加・大幅改訂するときはdocs/CONTENT_STANDARD.mdも読む。リスク・事故/脆弱性/実験の区別・役割別確認・証拠のあるチェックリストを確認する。
