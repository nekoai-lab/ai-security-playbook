## この教材の結論

2026年10月21日の公式発表に掲載された修正版は **22.23.4 / 24.22.1 / 26.12.1** です。同じ系列の修正版以降を基準に、現在の公式リリース情報も確認してください。この数字は今回の更新の基準で、将来の安全を保証するものではありません。

> 情報の確認日：2026年10月24日。対象の脆弱性があることと、個別のアプリで悪用できることは別です。実行経路が分からない場合は「未確認」として管理します。

## 公式に確認できる修正

[Node.jsの公式発表](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases)では、10件の脆弱性が掲載されています。高深刻度は次の4件です。

| CVE             | 問題                                          | 影響する系列 |
| --------------- | --------------------------------------------- | ------------ |
| CVE-2026-111497 | Brotli展開時の範囲外書き込み                  | 22 / 24 / 26 |
| CVE-2026-105482 | NUL文字を含むDNS名の切り詰め                  | 22 / 24 / 26 |
| CVE-2026-105483 | 全角数字のIPによるTLSホスト名検証の回避       | 24 / 26      |
| CVE-2026-106069 | IPとして解釈されるホスト名によるTLS検証の回避 | 22 / 24 / 26 |

残る6件は中・低深刻度で、HTTPのkeep-alive、証明書検証、乱数キャッシュ、ZIP処理、権限モデルなどが対象です。詳細は公式発表の各項目を参照してください。Brotliだけを見て更新対象を決めないことが大切です。

| 系列     | この更新の修正版           | 判断                                     |
| -------- | -------------------------- | ---------------------------------------- |
| 22.x     | 22.23.4                    | 同系列の修正版以降へ                     |
| 24.x     | 24.22.1                    | 同系列の修正版以降へ                     |
| 26.x     | 26.12.1                    | 同系列の修正版以降へ                     |
| 上記以外 | この発表に修正版の掲載なし | サポート状況を確認し、必要なら移行を計画 |

## Brotliの入力経路をたどる

Brotliはデータの圧縮形式です。公式はこの問題をリモートコード実行につながる範囲外書き込みとして説明しています。一方、手元のアプリでコード実行が成立するか、実際に悪用されたかは、その記載だけでは分かりません。

調査する入口の例：

- 外部URLを取得し、圧縮レスポンスを展開する処理。MCPやサーバー側の取得処理も含みます。
- 圧縮されたリクエスト本文を受け付けるAPI。ミドルウェアの版と設定を確認します。
- アップロードされた圧縮ファイルを展開する処理。

`fetch()`やExpressを使っていることだけで、すべての構成が影響を受けるとは断定できません。実際の実装、ライブラリの版、圧縮対応、入力元まで確認します。公開PoCの実行は確認手順に含めません。

## AIツールへの影響はどう考える？

アプリ本体・補助ツール・MCPのランタイムを分けます。Nodeの修正版番号を、BunやElectron、AIツール本体の修正済み判定に流用しないでください。

| 分かること               | それだけでは分からないこと                   |
| ------------------------ | -------------------------------------------- |
| 手元のNodeの版           | アプリ同梱Nodeや起動中MCPの版                |
| アプリを最新版にしたこと | 対象修正の取り込み、脆弱な処理への到達可能性 |
| 古いランタイムがあること | 侵害の有無、攻撃の成立                       |

元記事にある製品のバージョンは著者が観測した時点の実例です。全利用者の環境や製品全体の影響を示すものではありません。特定のClaude Code版を「修正済み」とする根拠は、この教材では確認できていません。

## 自分の環境を一つ確かめる

1. **対象を分ける。** 手元のNode、起動中のMCP、CI、本番のうち一つを選びます。一つ分かっても、ほかの対象まで確認できたことにはなりません。
2. **版を読む。** [安全に調べる確認コマンド](../commands/#手元のnodeを確認する)で、導入先と版を手元で調べます。この確認だけでは更新や停止を行いません。
3. **入力経路を調べる。** 上のBrotliの図に沿い、入力元・展開する処理・そのランタイムを確かめます。実装や設定が追えない範囲は「未確認」とします。

手元で新しく起動したNodeの版は、起動中のMCPやアプリ同梱Nodeの版の証明にはなりません。必要な対象は[起動中プロセスの確認](../commands/#起動中のプロセスを確認する)へ進みます。ログや出力をそのまま共有する必要はありません。

## 確認から対応まで

1. 自分のPC、MCP、CI、本番の実行版を記録する。
2. 外部入力が届くサービス、サポート外の系列、長時間起動中の処理を優先して調査する。
3. 導入方法に合った更新手順と、互換性・停止影響・戻し方を確認する。
4. 更新し、対象プロセスを再起動する。本番は必要に応じて再ビルド・再デプロイする。
5. 実行中の版と正常動作を再確認し、未確認の対象を残す。

確認後は、[更新を完了させるチェックリスト](../checklist/)で、再起動や動作確認の漏れを確かめられます。
