# FIELD NOTES — AI Security Playbook Design System v1.1

承認日: 2026-10-23。ユーザーが選択した「オレンジの帯のA案」を基準とする。
追加の確定要件: 脳の表現は使用せず、幾何学的なプロセッサーと積層チップへ置き換える。

## 方向性

「AIの安全を、解き明かそう。」を軸にした、探究のフィールドノート。
紙のような背景、黒いインク、大きく力強い日本語、朱色の帯、技術的な分解図を組み合わせる。
印象だけで危険をあおらず、本文は静かに読みやすく保つ。

## 正本

- tokens: `src/styles/tokens.css`
- layout / responsive styles: `src/styles/global.css`
- 共通部品: `src/components/`
- 実際の表示見本: `/ai-security-playbook/design-system/`
- 学習ルートのデータ: `src/data/learning-paths.ts`

| paper       | #f5f1e6 | 基本の紙背景                         |
| paper-light | #fbf8f0 | 表・カード・補助面                   |

大見出しの朱色は #e24100。明るいorangeを小さな本文へ流用しない。
注意・危険はそれぞれwarning/dangerの専用色とラベルを使う。
ブランドのorangeを「危険」や「修正済み」の状態判定として扱わない。

## 文字・余白・線

- 日本語: OSの読みやすいゴシック体。外部フォント取得は不要。
- 主見出し: 太いゴシック体、desktop 最大80px / mobile 32pxを基準。1行に詰めすぎない。
- 章の導入: 明朝体を少量使い、フィールドノートの編集感を作る。
- 本文: 16px、行高1.9。本文幅は最大40em。
- 補助ラベル: monospace 12px以上、短く。重要情報を小さな英語だけにしない。
- 余白: design/design-rules.json の spaceScale に従う。
- 線: 1px。角は基本0–2px。大きい角丸や多用する影に頼らない。

## 部品と契約

| Component      | Props                                 | 役割                                       |
| -------------- | ------------------------------------- | ------------------------------------------ |
| FieldButton    | href, variant=primary/text, label?    | 操作の優先度。hrefは実在する行き先         |
| FieldIcon      | kind=book/terminal/layers/compass/cat | 黒線の装飾図。意味は隣の文字で伝える       |
| SectionHeading | eyebrow, title, number?               | 見出しの階層                               |
| PathCard       | path, lessons                         | レベル名・番号・読み順・時間・次の行動     |
| Notice         | tone=note/warning/danger, title       | 前提、注意、危険。role=alertの乱用はしない |
| Flow           | steps, caption                        | 意味のある順序を持つ図解                   |
| DataTable      | slot                                  | キーボードで横スクロール可能な表           |

MDXでは必要な部品をimportして使う。tableは詳細ページでDataTableに自動割り当て。
色や文字は各教材で独自指定せず、共通tokenを参照する。

## 画面構成

トップ: ブランド → 見出し+イラスト → オレンジ帯 → 学習ルート → 注目教材 → 教材一覧 → 次のテーマ。
教材: パンくず → 見出し・更新日 → 目次+読みやすい本文 → 次の教材・出典への導線。
768px前後から単列へ。スマホは見出し→説明→操作→イラストの順。目次は本文の前。
スクロールを隠してレイアウト破綻をごまかさず、表とコードのみ局所スクロールにする。

## イラスト

黒のペン画・版画のような細密な線、控えめな紙の質感、朱色の配線。
図は部品の関係を探究したくなる構成にする。幾何学的プロセッサー、積層チップ、端末、資料、山、猫の探検家を使う。
**禁止: 脳、臓器、生体構造、グロテスクな表現、恐怖をあおるハッカーの写真。**
文字や操作を背景イラストへ焼き込まない。本文・ボタンはHTMLにする。
生成イラストを厳密なアーキテクチャ図として使わない。実際の仕組みは根拠のあるFlowや表で伝える。

## アクセシビリティ

キーボードフォーカスはblueの3px線。操作領域は原則44px以上。
ブランド色だけでレベルや状態を区別しない。番号と名称、注意ラベルを併用。
画像に適切なalt、装飾SVGにaria-hidden。reduced-motion時にアニメーションを止める。
320 / 375 / 1440pxとaxe自動検査で確認。自動検査だけで適合性の保証とはしない。

## 追加時の確認

1. 既存のtokenと部品で表現できるか。
2. 一次資料・更新日・未確認範囲が読めるか。
3. ブランドの装飾が、本文や操作を邪魔していないか。
4. スマホで見出し・図解・表が扱えるか。
5. 実装していない検索・ログインなどの操作を、見た目のために置いていないか。


## v1.1 / ロゴと案内役

正式ロゴはA「羅針盤と猫」。Headerとfaviconに使い、横にサイト名を置く。
C「オレンジのリュックを背負った探検猫」は学びの案内役。学習ルート入口、教材の読了位置、ガイド内の使い方見本に使う。
ロゴをCに置き換えたり、注意・危険の表示や一次資料の代わりに猫を置いたりしない。

- BrandMark: size、monochrome、class。隣接する文字が名称を伝える装飾画像。
- ExplorerCat: size、class。補助イラストとして扱う。
- ExplorerNote: title、compact、slot。次に取れる具体的な行動を短く示す。

ロゴの周囲は少なくとも本体の1/4を空け、32px未満では細部を読ませない。
公開ガイドは、ロゴ・色・文字・操作・ルート・図表・注意書き・画像・ページ構成・スマホ・教材制作・品質の12節。

## 検証の契約

数値契約はdesign/design-rules.json、意図はdesign/DESIGN.md、要求と証拠はdesign/SPEC_TRACE.md、残課題はdesign/UX_REVIEW.md。
`npm run design:audit` は手元の共通ハーネスを実行する。非公開エンジンを公開repoに転載しない。
型・ビルド・リンクの成功と、デザイン検品の合格は分けて報告する。

## ヘッダーナビゲーション

サイト名は明示改行を入れず通常幅で1行。文字拡大時は欠落より折返しを優先する。狭い画面では3つのナビを独立した行に並べ、枠と背景で操作領域を示す。現在のURLハッシュと一致するリンクだけを朱色の下線とaria-currentで示す。ページ内リンクであり、tabロールは使わない。GitHubは狭い画面でアイコン表示し、読み上げ名を残す。
